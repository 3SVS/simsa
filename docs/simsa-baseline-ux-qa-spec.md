# 지시서 — Baseline UX QA: 전 유저 프로젝트 기본 검수 (이벤트 트리거 + 비용 가드레일)

> **한 줄 요약:** 모든 유저 프로젝트의 검수에 baseline UX 루브릭(3층)을 기본 포함시키고,
> 배포 이벤트마다 diff-스코프로 재검수한다. 상시 폴링은 스모크만. run당/월간 비용 상한 강제.
>
> **작성:** 2026-07-05, Cowork 세션 (Bae 승인). 근거 데이터: `docs/ux-sweep-2026-07-05.md`,
> 유닛 이코노믹스 논의(아래 §6 표).

## 0. 배경 — 왜 지금

- simsa 자체가 기본 UX 결함(escape hatch 부재, 죽은 버튼, Enter 무반응, 에러 고착)을 오픈 직전까지
  누적했다. 원인은 "기준이 없어서"가 아니라 **기준이 실행되는 루프가 0이어서**다.
- 이 결함 클래스는 정적 도구(axe/Lighthouse)로 안 잡힌다. **플로우를 걸어야** 잡힌다 — 그리고
  그 파이프라인(Stage 260A visual completion check)이 이미 있다. 이 지시서는 **새 시스템이 아니라
  260A 확장 + 기본값 변경 + 이벤트 훅**이다.

## 1. 스코프

**지금 구현:**
1. baseline UX 루브릭 (git-tracked 데이터, 3층)
2. 배포-이벤트 트리거 재검수 (diff-스코프)
3. 상시 스모크 (LLM 0)
4. 비용 가드레일 (run 예산 + 일 cap + 월 상한 메트릭)
5. 결과의 checks/비개발자 리포트 표면 통합 + 듀얼 카탈로그 연동

**지금 구현하지 않음 (§7 염두만):** 티어 사다리, Simsa Lvl 2(dev 모드), 크레딧 종량제.

## 2. 루브릭 — 3층, git-tracked

`.conclave/` 계열과 동일하게 **git-tracked 버전드 데이터**로 관리 (answer-keys 원칙, decision #17).
루브릭 항목 스키마: `{ id, layer, rule, severity, detector, version }` — Zod 파싱 필수.

### Layer 1 — 기계식 (LLM 0, 결정적)
같은 브라우저 세션 안에서 함께 수집 (별도 run 금지 — 비용):
- axe-core 주입 (WCAG 자동화 가능 영역)
- 링크 크롤: 렌더된 내부 링크 404/dead 체크
- Core Web Vitals 기본값 (LCP/CLS 정도, Lighthouse 풀런은 선택)

### Layer 2 — 휴리스틱 4룰 (260A 확장) — **기계 2룰 + 상호작용 2룰로 분리 구현**
오탐·비용을 낮추기 위해 두 그룹으로 나눈다 (2026-07-05 리뷰 반영):

**L2-A 기계 검출 (DOM 검사, LLM 최소 — 오탐 낮음):**
1. **escape hatch** — 화면/스텝별 뒤로·취소·목록 경로 존재 (DOM에서 결정화 가능)
2. **무음 실패 금지** — 에러 표시 노드/핸들러 유무 검사

**L2-B 상호작용 필요 (INSPECTOR flow 실행 확장 = 크리티컬 패스):**
3. **모든 인터랙티브 요소는 반응한다** — 죽은 버튼, same-route no-op 링크, Enter 무반응 입력
4. **async 3-상태** — pending 표시 / 성공 피드백 / 에러+재시도 (에러 고착 금지)

> 현재 INSPECTOR(`inspector-run.mjs`)는 로드+스크린샷만 수행 (click/fill/press 0개).
> L2-B는 flow-plan 스키마를 **실제 실행**하는 상호작용 엔진 확장이 전제 — 이 스테이지 난이도의 80%.

### Layer 3 — 도메인 오버레이 (스키마만)
`domain` 태그(intake에서 이미 수집) → 오버레이 루브릭 선택. **이번 스테이지에서는 빈 오버레이 +
스키마만** 구현. 오버레이 콘텐츠 채우기는 후속.

## 3. 트리거 설계 — 카나리아와 역할 분리

| | 대상 | 주기 | LLM | 비용 |
|---|---|---|---|---|
| 카나리아 (기존) | simsa 자체 | 15분 cron | 0 | 무시 가능 |
| **스모크 (신규)** | 유저 프로젝트 배포 URL | 15-30분 cron | **0** (HTTP + 핵심 화면 로드만) | ~$0.5-1/repo/월 |
| **풀 검수 (신규)** | 유저 프로젝트 | **이벤트만**: 배포 성공(platform-* deployment-status) · PR push · 수동 버튼 | Haiku급 워커 + 상위모델 리포트 합성 1콜 | §6 |

**절대 금지:** 유저 프로젝트에 풀 검수 상시 폴링 (15분 간격 시 월 ~$720/repo — 즉사 수치).

**diff-스코프:** 재검수 시 라우트별 DOM-hash 비교 → 미변경 라우트 스킵. 변경 라우트만 L2 워크.
첫 검수만 전체.

## 4. 실행 규칙

- **모든 LLM 콜은 효율 게이트 경유** (직접 SDK 호출 금지 — 기존 절대 원칙). 루브릭 프롬프트는 캐시.
- **유저 앱 안전 규칙 (260A 금지 필터로는 부족 — 상호작용 확장 시 필수 강화):**
  - **프리뷰 URL 우선**: 배포 이벤트가 프리뷰/스테이징 URL을 제공하면 L2-B는 반드시 프리뷰에서 실행.
  - **프로덕션에서 실행할 때** L2-B는 안전 화이트리스트 요소만: 네비게이션·토글·검색/필터 입력.
    폼 제출(회원가입·문의·발송), 결제·삭제·외부 발신류는 요소 텍스트/타입 휴리스틱으로 차단 —
    "일반 버튼처럼 보이는 부작용 CTA"가 기본 위협 모델.
  - type 입력은 명백한 검색/필터 필드만, 테스트 문자열 고정.
  - 로그인 벽 뒤는 스코프 밖 — 리포트에 "확인 못 한 영역"으로 표기.
- 결과 포맷: 기존 blocker 포맷 + `rubricItemId` 필드. 비개발자 리포트(`nondev-report.ts`)로
  무엇이/왜/어떻게 3줄 번역. checks 화면의 "판정 한 줄 + 다음 행동" 상단 배치 재사용.
- 메모리: fail→fix→재검수 통과 = answer-keys 기록 / 동일 룰 반복 위반 = failure-catalog 기록
  (기존 듀얼 카탈로그, 새 저장소 만들지 말 것).

## 5. 비용 가드레일 (하드 요구사항)

1. **run당 예산 상한**: 기본 $0.60. 효율 게이트 budget enforcement로 강제 — 초과 시 부분 결과로 종료 + 리포트에 표기.
2. **무료 사용자 cap**: 배포 시 1회 + 일 1회. tier-2 에스컬레이션 금지 (워커 Haiku급 고정).
3. **repo별 월 비용 메트릭**: 효율 게이트 metrics에 `qa_cost_usd{repo}` 적재. 월 상한(기본 $10) 도달 시
   자동 중단 + 운영자 알림 (기존 Telegram 통지 재사용).
4. cap/상한 값은 전부 config로 (`.conclaverc.json` + central-plane env) — 하드코딩 금지.
   **이 cap 설계는 §7 티어 게이트로 재사용될 예정이므로, "플랜별 값 주입"이 가능한 형태로.**

## 7. ★ 염두 사항 — 구현 금지, 설계 호환만 유지

> 아래는 확정 계획이 아니다. 지금 구현하지 말 것. 단, §5의 cap/메트릭 구조가 아래와 충돌하지 않게만 설계할 것.

- **티어 사다리(안):** Free(일 cap) → Pro $29(비개발자, diff-스코프+월 상한) → **Dev "Lvl 2" $49-59**
  (개발자 용어 모드 + CLI/MCP/CI 통합 + tier-2 상한 확대) → 초과분은 크레딧 종량제(한계비용 ×10).
- **Lvl 2 게이트는 사용량이 아니라 행동 신호** (repo 연결, PR 워크플로우, raw 로그 열람 + cap 도달 조합).
  사용량 많은 초보는 크레딧으로 흡수.
- **용어 모드**는 별도 제품/화면이 아니라 dictionary에 dev-dialect 축 추가로 처리 (카피 2벌 유지 금지).
- 근거: 유저 지갑 앵커 Lovable $25·Cursor $20·CodeRabbit $12-30 [확정, 공개가]. 구독 = 앵커가 + 비용
  엔지니어링 4-6x, 크레딧 = 10x, 블렌디드 COGS 15-25% 목표.

## 8. 수용 기준 (acceptance)

1. **도그푸드 재현 검출**: ux-sweep에서 잡았던 위반 4종(escape hatch 부재 / Enter 무반응 /
   에러 고착 버튼 / 무음 실패)을 재현한 픽스처 앱에서 4/4 검출. simsa 자신(#217 이후 main)에서는
   해당 4종 0건 통과.
1-b. **오탐 상한**: 정상 패턴 픽스처(살아있는 버튼·정상 escape hatch·정상 에러 처리)에서 **오탐 0건**.
   프로덕션에서는 리포트 항목에 "이 지적이 틀렸어요" 액션을 두고 오탐 신고율을 메트릭으로 적재
   (유저가 오탐 하나에 리포트 전체 신뢰를 버리는 구조 방지 — L2-B 판정의 성패 지표).
2. 배포 이벤트 → 자동 재검수 → checks 화면에 rubricItemId 포함 결과 표시, E2E 1회 시연.
3. run 예산 상한 초과 시 부분 결과 종료 동작 테스트 존재.
4. 일 cap 2회째 요청이 거부되고 사용자에게 사유가 보이는 테스트 존재.
5. `node --test`, seam에서 mock (실제 LLM/브라우저 호출 없는 테스트). CI green 후 머지 —
   Vercel을 CI로 쓰지 않는다.

## 8-b. 구현 순서와 타이밍 (2026-07-05 확정)

**오픈 블로커 아님.** 오픈의 마지막 관문은 휴먼 QA 3바퀴. 이 시스템은 오픈 직후 첫 스프린트.
단 **PR1은 순수 데이터라 오픈과 병행 가능** — 지금 착수 승인.

```

PR2: ★INSPECTOR flow 실행 확장 (L2-B 엔진)    — 오픈 후, 크리티컬 패스
PR3: 비용 가드레일 (BudgetTracker 배선, §5)   — 오픈 후
PR4: 이벤트 트리거 + diff-스코프              — 오픈 후
PR5: checks 표면 + 듀얼 카탈로그 + 픽스처(§8) — 오픈 후
```

재사용 확인됨: BudgetTracker/BudgetExceededError(§5.1은 배선), flow-plan 스키마 + 금지 필터(§4 기반),
