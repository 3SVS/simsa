### 1-1. 벤치 하네스(`tools/simsa-inspection-fixtures/agent-v2-bench1-local.mjs`)

- v1 하네스의 앱 목록·A1~A10 주입·사전 등록 정답지를 그대로 가져와 v2 실행기로 돌린다.
- 칸 단위로 채점한다: 짚음(원인 분류 포함), 반대, 없는 결함, 파생(같은 원인 묶음), 새벽 전용 칸, 앱 결정.
- 앱을 동시에 돌릴 수 있고, 반복 횟수를 지정할 수 있다.

### 1-2. 리포트 변환(`src/v2-report.ts`)

- v2 판정을 기존 agent 리포트 모양(기준 표·한 줄·메모)으로 옮긴다. 결정은 기존 규칙(`decideAgentVerdict`)으로 내서 화면과 결정이 어긋나지 않는다.
- pass는 `exercised = { stateChange: true, verified: confirmed }`로 옮긴다.
- 의도 불일치는 표에 fail로 넣고 이유 앞에 "생각과 달라요: "를 붙인다.
- 첫 화면 즉시 고장은 "앱 없음"으로 옮긴다.
- v2 전용 블록 `report.v2`에는 다음을 싣는다. 데이터(실패 사건 라벨)의 원천이 이 블록이다.
  - 판정, 재실행 확인 여부, 강등 사유.
  - 원인(분류·근거·위치·코드 조각·본 것).
  - 결함 묶음, 의도 불일치.
  - 고침(검증된 것·못 고침·가정·차이·고친 파일). 고친 파일은 검증을 통과했을 때만 싣는다.
  - 인용 증거물 요약(원문 300자 상한).

테스트:
- v2 106개 통과(S7 신규: 리포트 변환 5, 이미지 닫힘 3, 고치기 규칙 1, 마감 표현 1).
- e2e 1개: 스태프 게이트 → 디스패치 `version: v2` → v2 실행 → 리포트 변환 → 완료 콜백 → 저장된 `report_json`이 `engine: agent` + `engineVersion: v2`. 실제 라우트와 SQLite로 돌린다.
- 새 동작 테스트는 수정 전 코드에서 실패하는 것을 확인했다.

## 2. 배포 전 주의

- **배포는 하지 않았다.** 검사 컨테이너 이미지와 central-plane Worker 배포는 각각 승인이 필요하다(`deploy central-plane approved.` 등).
- 프로덕션 v2의 LLM은 Worker 프록시를 거쳐 tier `strong`을 쓴다. 어느 모델인지는 서버 설정(`INSPECT_AGENT_MODEL`)이 정한다.
- **2026-10-23 현재 OpenAI 크레딧이 소진되어 있다.** 프로덕션 프로브에서 gpt-5.4·5.4-mini·5.6-sol이 전부 429였고, Anthropic Opus 5.5는 usable이었다. 이 상태로는 v1·v2 모두 OpenAI 경로가 막힌다. 충전, 또는 `ANTHROPIC_ENABLED` 재활성화(별도 승인)가 먼저다.
