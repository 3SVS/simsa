트레인: `train v2-S6 start approved.` (Bae 2026-10-23). 설계: `docs/simsa-inspector-v2-design-2026-10-07.md` §2.2-7 · S6 완료 증거 "수정본 재실행 통과 테스트".

| 단계 | 내용 | 근거(실측) |

| 실행 분리 | 각 기준 실행(그리고 고친 파일 검증 실행)에는 공통 증거물(정찰·사실·계획)과 그 실행의 증거물만 보인다. 다른 실행의 증거물을 인용한 판정은 `cites_other_run`으로 기각한다 | 실측 F4: 검증 실행이 원본의 오류 로그를 인용해 첫 턴에 fail |
| 못 고침 | 편집 없이 이유만 답하면(서버·DB·외부 키 필요) 오류가 아니라 `cannot_fix_in_single_file` | 실측 F3·F6·F13이 `no_edits` 오류로 기록됨 |

S6a의 분류 순서:
1. 의도 불일치 판정 → `intent_mismatch`.
2. 이 기준을 덮는 가설의 정적 사실이 있고, 실행 증거가 그 사실과 맞으면 → 그 분류.
3. 이 기준 실행 중 콘솔에 네트워크 실패가 있으면 → `missing_backend_config`. 잡히지 않은 오류가 있으면 → `runtime_error`.
4. 그래도 정하지 못하면 판정 문장으로 분류한다.

S6c의 고치기 순서:
1. 기준, 재현 순서, 원인(분류·위치·코드 조각·본 것)을 주고 정확히 한 번 맞는 편집만 받는다(v1 B5 재사용).
2. 고친 파일을 그 주소에 끼워 넣는다.
3. 실패했던 기준을 v2 실행(검증기 + 재실행 확인)으로 다시 돌린다.
4. 확인된 pass만 `validated`로 인정하고 고친 파일을 제공한다.
5. 끝나면 끼움을 되돌린다.

테스트: v2 96개(S6 신규 13). 새 동작 테스트는 수정 전 코드에서 실패하는 것을 확인했다. central-plane 전체 3484/3484 통과.
- [주석] 측정과 동시에 돌렸을 때 2개가 실패했다. 측정 없이 다시 돌리면 0개였다. 부하로 생긴 시간 초과로 보이지만, 어떤 테스트였는지는 기록하지 못했다.

### 주의 — 고친 파일의 한계 (보고에 반드시 함께 실어야 함)

- **F6의 고친 파일은 "이 기기 브라우저에만 저장"한다(localStorage).** 기준("목록에 저장되어 나타나야")은 만족하지만, 다른 기기·다른 사람과는 공유되지 않는다. 사용자에게 이 한계를 함께 알려야 한다. 공유가 의도라면 서버가 필요하다.
- **F4의 고친 파일은 환율을 1400으로 지어 넣었다.** 픽스처에 실제 환율이 없었기 때문이다. 실제 사용자의 앱에서 모델이 업무 값(가격·환율·세율)을 지어 넣으면 "작동하지만 틀린 앱"이 된다.
  - 다음 조치: 고치기 요청에 "모르는 값은 표시된 자리표시자로 두고 cannotFix/메모에 적는다" 규칙을 넣는다. 그리고 고친 파일 보고에 "지어 넣은 값" 목록을 싣는다.
- **F10은 이번에도 mismatch가 아니라 fail(분류 `broken_action`)이었다.** 결정은 맞지만 "의도와 다름"을 매번 같게 짚지는 못한다(S5부터 이어지는 흔들림). 반복 측정에서 비율을 재야 한다.
