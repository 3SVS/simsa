## S1 — 증거물 저장소 · 판정 스키마 · 기계 검증기 (`src/evidence-chain.ts`)

| 장치 | 규칙 |
|---|---|
| 저장소 | id `E1…`, kind 닫힌 7종(request·storage·source·screen·console·diff·context), 원문 상한 4000자·요약 240자, 가림 함수, 개수 상한 500(넘으면 `truncated`) |
| 판정 파서 | LLM 판정 JSON 엄격: verdict 4종(pass·fail·not_verified·mismatch) · `E` id 형식 · 인용(quotes) ≥1(not_verified 제외) — 어긋나면 판정 없음 |
| 기계 검증기(LLM 0) | ① 인용 증거물 없음·없는 id → 강등 ② 인용 문구가 그 증거물 원문에 없음 → 강등(지어낸 인용) ③ **pass = 상태 변화 증거물**(쓰기 2xx · 저장소 변화 · 전후 차이 · 새 브라우저/역할 관찰) ④ **fail = 별개 재실행 증거물에 같은 문구** — 통과 못 하면 not_verified + 사유, 리포트(accepted)에 오르지 않는다 |

## S2 — 정찰 (`src/recon.ts` 순수 판단 + `inspector-container/recon-collect.mjs` 수집)

- 수집: 첫 화면 HTML + 같은 출처 스크립트 + 동적 import 1단계, **GET만·실행 없음**, 파일 20·1.5MB·합계 6MB·10초 상한.
- 첫 화면 즉시 판정: 기존 호스트 404 판별기 재사용(`nondev-report.ts` — 같은 판단을 두 곳에 두지 않음) → `deployment_not_found`·`missing_index_file`·`page_not_found`·`server_error`·`blank_page`, 401/403은 로그인 벽(고장 아님).
- 정적 사실(가설 근거, 판정 아님 — V-4): R1 백엔드 미설정 · R2 기기에만 저장 · R3 UTC "오늘"(**현지 시간 보정 제외** — 실험 오발화 수정) · R4 사용자 API 키 필요 · R5 서버 렌더(서버 시간대 날짜 가설). 사실은 증거물(kind `source`)로 남아 id로 인용된다.
