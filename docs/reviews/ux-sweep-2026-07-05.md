## P0 — Blocker (오픈 전 필수)

1. **`app/projects/new/intake/page.tsx` — 나가는 네비게이션 0개** *(검증됨)*
   1,966줄 전체에 `router.*` / `<Link>`가 하나도 없음. 인테이크 플로우에 들어가면 브라우저 뒤로가기 외엔 탈출 불가.
   → 상단에 `/projects/new`(또는 `/projects`)로 가는 back Link 추가.

2. **커스텀 답변 입력 — Enter 키 무반응** *(검증됨)*
   `app/projects/new/page.tsx:334`, `components/QuestionCard.tsx:75` — `onBlur`로만 커밋. Enter를 눌러도 아무 일 없음.
   → `onKeyDown` Enter 핸들러 추가 (두 곳 동일 패턴, 같은 커밋에서 함께).

3. **벤치마크 생성 버튼 — 에러 후 영구 고착** *(검증됨)*
   `app/projects/[id]/experiment/page.tsx:286` — 실패 시 `benchPhase="error"`로 남고 리셋 경로 없음. 재시도하려면 새로고침.
   → 에러 시 idle 복귀(타임아웃 or 에러 배너 + 재시도 버튼).

4. **폼에 onSubmit 없음 — Enter 제출 불가** *(설정 페이지 검증됨)*
   `app/projects/[id]/settings/page.tsx` (Telegram/Email 설정), `app/projects/[id]/experiment/page.tsx:374-388` (실험 생성) — `<form onSubmit>` 미사용. 입력 후 Enter가 죽어 있음.
   → `<form onSubmit={e => {e.preventDefault(); handler();}}>` 래핑.

## P1 — Major

5. **저장 실패 무음 처리**: `app/projects/new/page.tsx:137`, `app/projects/[id]/sources/[sourceId]/draft/page.tsx:134` *(검증됨)* — `saveProjectToDb(...).catch(() => undefined)`. DB 저장이 실패해도 성공처럼 이동. 로컬 저장은 됐으므로 최소한 "서버 동기화 실패" 배너 필요.
6. **에러 상태 미표시 로드**: experiment / checks / benchmark / github 페이지 — API 실패 시 사용자에게 보이는 에러 UI 없음 (`t.errors.loadFailed` 키는 정의돼 있으나 미사용 구간 존재).
7. **에러 후 재시도 불가 패턴 반복**: `settings/page.tsx:126` `tgSavePhase="error"` 등 — P0-3과 동일 계열. `rg "Phase\(\"error\"\)"`로 전수 확인 후 일괄 수정 권장.
8. **userKey 부재 시 무음 실패**: `experiment/page.tsx:258, 278` — 조건 미충족 시 `return`만 하고 피드백 없음.
9. **rate-limit 처리 불일치**: `/projects/new`엔 `rateLimitMsg` 있음, 형제 플로우(인테이크·draft)엔 없음.

## 재발 방지 (이번 패턴 → 체크리스트화)

이번 결함은 전부 4개 룰로 수렴. baseline UX 루브릭 Phase 0 항목으로 등록 권장:

- 모든 화면에 escape hatch (뒤로/취소/목록) 존재
- 모든 인터랙티브 요소는 반응한다 (same-route Link, Enter 키, disabled 고착 금지)
- 모든 async 액션은 3-상태 (pending 표시 / 성공 피드백 / 에러 + 재시도)
- 실패는 무음 처리 금지 (`.catch(() => undefined)` 신규 도입 금지, 기존 건 배너로)
