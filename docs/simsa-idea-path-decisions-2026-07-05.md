### D1-b. 회귀 루프 (2026-07-05 확정 — 팩 구현에 필수 포함, "유저가 돌아오길 기다리기" 금지)

**1겹 — 팩 내장 회귀 훅 (핵심, 비용 ~0):**
- 팩의 마지막 지시문 고정: *"구현 완료 후 위 수용기준으로 자가 점검하고, 사용자에게 배포 URL을
  `{앱URL}/p/{projectId}/connect` 에 붙여넣어 검수받도록 안내하라."*
  → **유저의 에이전트가 빌드 완료 시 스스로 Simsa 재진입을 안내**하게 만든다.
- 재진입 딥링크는 프로젝트 스코프 — 열면 해당 프로젝트 컨텍스트 즉시 복원, URL 입력창 포커스.
- 다른 기기에서 돌아오는 경우 대비 → D2 claim(인증 후 동기화)과 연결.
- (Lvl 2 결, 지금은 팩에 주석만) Claude Code/Cursor용 팩 변형: simsa MCP 서버 설정 포함 →
  에이전트가 완료 시 검수 자동 트리거.

**2겹 — 대기 상태의 제품화:**
- 프로젝트 상태 추가: `아이디어 → 팩 발급됨(building) → URL 연결됨 → 검수`.
- building 상태 카드에 "앱이 생겼나요? URL 연결" CTA 상시 노출. URL 붙여넣는 즉시 검수 자동 시작
  (돌아온 보상이 3초 안에).

**3겹 — 리마인더 (보조):**
- 팩 export 시점 = 이메일 수집 명분 ("돌아올 링크를 보내드릴게요" — 강요 아님, D2 soft 인증과 정합).
- 24-48h 후 1통: "앱 만들어지고 있나요? URL 붙여넣으면 확인해드려요" + 딥링크. Resend 재사용.
- 오픈율 낮음 [추정] — 보조 장치로만. 승부는 1겹.

## D2. 인증 = Soft 인증
- 가입 즉시 사용 가능. **서버 귀속(claim)·기기 간 동기화는 이메일 인증 후**.
- `requireEmailVerification`은 hard 차단이 아니라 claim 게이트로 배선. 발송은 Resend 재사용.
- 미인증 상태 UI: "인증하면 다른 기기에서도 프로젝트를 볼 수 있어요" 배너 (강요 아닌 안내).

## D3. 로그인 수단 = Google 추가
- better-auth Google provider 활성. 카카오는 오픈 후 가입 지표 보고 검토 (지금 구현 금지).
- GitHub OAuth는 비활성 유지 (Lvl 2 시 활성).
