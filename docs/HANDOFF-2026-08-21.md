## [추가 3] ★배포 후 실측 — P1-2의 진범은 **403 egress**(A-1 가설 반증)

#487 배포(deployedSha=`4d1f99a`) 후 같은 동시 프로브를 돌리자 **실패가 그대로**였다
(라운드1 1/4, 라운드2 0/4 성공, 여전히 ~9초). 그리고 **A-2 계측이 즉시 원인을 뱉었다**:

```
{"event":"llm_failure","final_status":403,"failure_class":"egress",
 "attempts":6,"latency_ms":8798,"reason":"attempts_exhausted"}
[anthropic-fetch] attempt 1~6 got 403 — retrying     ← 6회 전부 403
```

- **진범 = Anthropic이 Cloudflare egress IP에 403 "Request not allowed"**. 용량(429/529) 아님.
  → **A-1의 전제(용량 오류)는 틀렸다.** A-1 자체는 무해·유효(429/529가 올 때는 제대로 처리)하지만
  이번 실패에는 효과가 없다. **A-2를 먼저 넣은 판단이 30분 만에 가설을 반증했다** — 이게 계측의 값.
- **AI Gateway를 경유하는데도 403이 난다.** 코드 주석의 "게이트웨이가 이 문제를 sidestep한다"는
  전제가 실측과 다르다(게이트웨이도 CF 인프라 → 상대편에겐 여전히 CF IP).
- 동시 요청에서 유독 나쁜 이유: **재시도 6회가 같은 뜨거운 IP로 나가는 것**으로 보인다.
  그래서 **횟수·대기를 늘리는 방향은 소용이 적다 — 경로를 바꿔야 한다.**
- 부수 실측(성공 호출): check 5.0~5.4초(output 1,100~1,200토큰 = max_tokens 4000의 30% →
  **잘림 가설도 확정 폐기**) · generate 28.9초.
