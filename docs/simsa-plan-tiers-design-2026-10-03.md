> 티어: **T2-P**(과금·프로덕션 데이터). 이 문서는 제안이며, Bae의 `design lock approved`(D-24) 전에는 아무것도 발효되지 않는다.

## 0. 근본 문제

지금은 플랜이 `free | paid` 둘뿐이고(`apps/central-plane/src/plan.ts`), 플랜으로 갈리는 것은 협의체 검수 하나다(`routes/workspace.ts` RC-4). **횟수 상한은 플랜과 무관하게 모두 같다**(`workspace/beta-limits.ts`: 새 프로젝트 20/일, 검수 10/일, 수리 5/일 …). 그래서
1. 무료 사용자가 원가가 가장 큰 경로(생성 LLM·검수 컨테이너)를 유료와 같은 양만큼 쓴다.
2. 유료로 올라갈 이유가 기능 하나(협의체)뿐이다.
3. 상한이 익명 `userKey` 기준이라 키를 새로 받으면 초기화된다.

## 2. 결정 (D-24)

### D-24.1 [LOCKED 제안] 티어는 무료·베이직·프로 3단, 플랜→한도는 한 표에서만
- 모든 플랜 차등(기능·횟수)은 `apps/central-plane/src/workspace/entitlements.ts`의 **단일 표**에서 나온다. 라우트에 `plan === "paid"` 같은 분기를 새로 쓰지 않는다.
- 자격 조회 실패는 **무료로 fail-safe**(RC-4와 같은 원칙: 막지도, 올려주지도 않는다).

### D-24.2 [LOCKED 제안] 새 프로젝트 생성 상한 — 무료·베이직 하루 1개
- 세는 대상: **새 프로젝트 생성만**(세 문 모두 — 만들기·기존 앱·아이디어). 같은 프로젝트의 재저장·검수·재검수·수리는 세지 않는다(그건 D-24.4 표).
- **삭제해도 돌려주지 않는다**(만들고 지우기 반복으로 우회 방지).
- 집계 키(병행 — 둘 중 하나라도 차면 거절):
  - 로그인 사용자: **계정**(auth 사용자 id) 기준 티어 한도
  - 익명 사용자: **네트워크**(비밀 키 HMAC, IPv6 /64 정규화 — #566·#580) 기준 무료 한도
  - 로그인한 무료·베이직도 네트워크 상한을 함께 본다(계정 여러 개로 우회 방지). 단 공용 와이파이·사무실을 위해 네트워크 몫은 계정 몫보다 크게 둔다([PILOT] 3).
  - 프로(결제로 신원 확인됨)는 네트워크 상한을 적용하지 않는다(서비스 전체 천장만).
- 날짜 경계: 기존 버킷과 같은 **UTC 자정(= 한국 오전 9시)**. 화면에는 사용자 현지 시각으로 "내일 오전 9시에 다시 만들 수 있어요"처럼 표시한다.

### D-24.3 [LOCKED 제안] 막힘은 막다른 길이 아니다
- 상한에 닿기 **전에** 새 프로젝트 화면에 "오늘 새 프로젝트 1개 중 0개 남음"을 보여준다.
- 거절 응답은 429 + `{ kind: "project_create", tier, limit, resetAt }`. 화면은 ① 기존 프로젝트에서 계속하기 ② 다시 만들 수 있는 시각 ③ 베이직·프로 안내(결제 준비 전에는 "문의"로) 세 갈래를 준다.
- 서버가 집행한다 — UI 숨김만으로 게이팅하지 않는다(RC-4와 동일).

### D-24.5 [OPEN] 가격
- 베이직·프로 월 가격은 **D-22 공식에 실측 원가를 넣어** 정한다. 입력: `llm_usage`(0070) 실적재 + 검수 컨테이너 원가 + 지원 시간. 지금은 llm_usage 실적재가 **미측정**이라 숫자를 쓰지 않는다.
- 재검토 트리거: llm_usage 2주 실적재 또는 파일럿 (b)(c) 완료 중 먼저 오는 것.

### D-24.6 [OPEN] 결과 보관 기간 차등
- 개인정보처리방침의 보유 기간 고지와 묶인다. 방침 개정과 같은 PR에서만 시행.

**놓치기 쉬운 선행 조건**
1. **감시·검증 장비가 막힌다.** canary(`.github/workflows/canary.yml`), `anonymous-smoke.mjs`, `journey-audit`, `dev-spec-probe` 등은 매 실행마다 새 프로젝트를 만든다. 같은 러너 네트워크에서 하루 1개면 **두 번째 실행부터 전부 빨간불** → 내부 토큰 헤더로만 켜지는 면제(서비스 천장은 그대로)를 T-2와 같은 PR에 넣는다.
2. **파일럿 사용자.** (b)(c) 파일럿 참가자는 하루에 여러 앱을 넣을 수 있다 → 파일럿 개시 전 `plan_grants`로 베이직/프로 부여.
3. **계정 기준 집계는 로그인 사용자 식별자가 서버에 있어야 한다.** 익명→로그인 승격(claim) 시 그날 익명으로 쓴 횟수를 계정에 합산한다(승격으로 초기화되는 우회 방지).
4. **방침 고지.** 네트워크 HMAC 기반 집계는 #566에서 이미 고지됨. 계정 기준 횟수 기록은 기존 "요청 횟수 제한 기록" 범위 — 문구 확인만.
