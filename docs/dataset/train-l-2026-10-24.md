# Train L — 실패 데이터 라벨: 스키마 · 기계 후보 · 저장 · 집계 (2026-10-24)

승인: `train L start approved.` (Bae 2026-10-24). 규약 정본: `docs/simsa-labeling-design-2026-10-20.md` (2026-10-21 LOCKED). 이 PR에서 main에 함께 들였다. 축 정의는 `docs/simsa-index-design-2026-10-18.md` §5.1이다.

## 왜

Simsa의 본체는 "AI 에이전트로 만든 제품이 어디서 실패하는가"의 데이터다(Bae 10-20). 검수 엔진 v2(S1~S7)가 그 실패를 증거와 함께 찾는다. 이 트레인은 그 결과를 **판매·통계 단위의 기록**으로 바꿔 쌓는다.

## 만든 것

| 단계 | 파일 | 내용 |
|---|---|---|
| L1 스키마 | `src/dataset/labels.ts` | 아래 1 참고 |
| L2 기계 후보 | `src/dataset/machine-candidates.ts` | v2 리포트 → 판정 + 실패 사건 후보(§7). **증거 사슬이 있는 것만** 옮긴다. 아래 2 참고 |
| L3 저장 | `migrations/0076_failure_labels.sql` · `src/dataset/record.ts` | 아래 3 참고 |
| L4 C13 분류 | `src/v2-report.ts` | 기존 빌더 × 결함 분류 집계(`inspection_defects`)도 v2 리포트에서는 증거 기반 원인을 쓴다(전에는 판정 문장 단어 맞추기) |
| L5 집계 | `GET /admin/failure-stats` | 빌더 × 여정 단계 × 증상 × 결함 분류 × 심각도. 실패 건수·런 수·앱 수. 출처를 섞지 않는다(기본 machine). 런 안의 같은 결함 묶음은 1건(첫 지점 규칙). 내부 토큰만 받는다 |

### 1. L1 스키마

- 설계 §1~§3·§9를 Zod로 옮겼다: 앱 카드, 기준 판정 H1~H8, 실패 사건 W1·W2·W3·Y·C·K·S·R·A·P·X.
- 출처를 machine · labeler_agent · user로 나눈다.
- 모든 행에 버전 4개를 단다.
- append-only다(고치면 `supersedes`).
- pass·fail에는 증거가 필수다.

### 2. L2 기계 후보 규칙

- v1 리포트는 옮기지 않는다.
- 실패 사건은 재실행으로 확인된 fail·mismatch만 만든다.
- 원인 층 C는 관찰 근거(정적 사실·콘솔)가 있을 때만 채운다. 없으면 `unknown`.
- 재현 R은 단정하지 않고 `reproduced 2/2`로만 남긴다.
- 기계만의 사유는 사람 어휘로 옮기지 않고 `machineReasons`에 둔다.
- 여정 단계는 **실패 문장 먼저, 기준 문장은 그다음**으로 정한다. 예: 벤치 A5 "새로고침해도 남는다(다른 방문자에게도)"에서 실패가 "새로고침하면 사라진다"면 persist다.

### 3. L3 저장

- 표 2개를 새로 만든다(additive, append-only).
- **닫힌 어휘 칸만 저장한다.** 화면 글자 인용·판정 문장·행동 기록·앱 주소는 넣지 않는다. 사용자 앱 화면에는 다른 사람의 정보가 있을 수 있기 때문이다(C13과 같은 원칙).
- 앱은 주소 해시(`app_…`), 화면은 정규화한 경로로만 남긴다.
- 검수 완료 콜백에서 v2 리포트이고 운영 정보 기록이 허용된 런만 쓴다. 표가 없으면 조용히 건너뛴다.

테스트:
- 스키마·후보 7개.
- 저장·집계 4개(실제 마이그레이션 SQLite). 연락처·이름·주소·문장이 저장되지 않는지 확인한다.
- e2e 1개(완료 콜백 → 판정 행).
- L4 1개. 새 동작 테스트는 수정 전에 실패하는 것을 확인했다(L4: 옛 분류 `not_shared_across_users`).

## 아직 아닌 것 (다음 단계)

- **라벨링 에이전트**(설계 §0.0): 검수와 분리된 모드, 두 벤더 블라인드 패스, 사전 등록 정답지로 정확도 측정. 데이터셋 정답은 이것이 만든다. 지금 쌓는 것은 기계 **후보**다.
- **사용자 마이크로 라벨 UI**(§8.5): 결과 뒤에 한 번 누르는 질문을 두고, `source=user`로 저장한다.
- **앱 카드 저장**(빌드 날짜·수정 횟수·스택)과 X2~X9 축.
- 루브릭 사례 30건·캘리브레이션 세트(설계 §12-2).

## 배포 순서 (각각 승인 필요)
