# Train L2 — 라벨링 에이전트: 블라인드 라벨러 · 두 벤더 패스 · 일치도 · 정답지 채점 (2026-11-02)

승인: `train L2 start approved` (Bae 2026-10-27). 규약 정본: `docs/simsa-labeling-design-2026-10-20.md` §0.0·§5·§6 (LOCKED). 머지·배포·프로덕션 저장 배선은 이 트레인 범위 밖이다.

## 왜

라벨 품질이 곧 데이터의 값이다. 기계 후보(train L)는 검수 엔진이 스스로 붙인 라벨이라 엔진의 실수가 그대로 남는다. §0.0의 라벨러는 엔진과 **분리된 모드**로, 엔진의 분석을 보지 않고(블라인드) 같은 앱을 다시 해 보며 라벨을 붙인다. 실패는 3번 재현해 확인한다. 이 라벨은 **다른 벤더 두 패스**로 붙여 일치도를 재고, **사전 등록 정답지**로만 정확도를 잰다.

## 약한 곳 (다음 트레인 입력)

- **원인 층 C κ 0.29.** 두 벤더가 같은 실패를 보고 `backend_missing`·`external_integration`·`unknown`으로 갈린다. 관찰 근거 없이 원인을 고르는 경향이 남아 있다. 판매용 통계에서 C를 쓰기 전에 C 정답지(픽스처별 원인)를 사전 등록해 따로 재야 한다.
- **픽스처 14개는 작다.** 목표 통과는 "이 규모에서 깨지지 않았다"는 뜻이지 일반화 증거가 아니다. 벤치 #2·통제 벤치마크(로드맵 ②.5)에서 다시 잰다.
- **F13류(앱 키 필요)의 경계.** "설정이 필요하다는 안내가 나온다"를 실패로 볼지 확인 불가로 볼지는 정답지가 둘 다 허용한다. 통계 집계에서는 둘을 따로 세야 섞이지 않는다.
