# Simsa 사업 전략 — 단기 데이터 · 장기 모델 선택 (2026-10-05, Bae)

> 상위 문서: `simsa-prd.md`, `simsa-bm-economics-2026-09-27.md`, `simsa-pricing-entity-consent-plan-2026-09-27.md`. 이 문서는 그 위에 **방향**을 더한다(가격·과금 결정은 바꾸지 않는다 — 엔진 밖 결정은 엔진 실측 통과 후).

## 1. 한 문장
**비영어권 비개발자가 AI로 만든 결과물이 실제로 작동하는지, 원래 원한 기준으로 독립 검수하고 고치게 해 주는 서비스.** 그 과정에서 모이는 "빌더·모델별 실패 지점" 데이터로, 장기적으로는 유저 의도에 가장 맞는 모델·빌더를 골라 결과물을 만들어 주는 플랫폼이 된다.

## 2. 단기 (지금 ~ 엔진 검증 후 6개월): 측정·검수 + 데이터 수집
- **무엇을 준다:** 주소·아이디어·저장소/PRD 세 갈래 → 의도 확인 질문 → 정답지(완료 조건) → AI 브라우저 검사(로그인 세 방식, 화면·버튼 점검) → 조건별 판정 → 빌더팩/고친 파일/자동 수정 → 재검사.
- **무엇을 모은다(동의한 경우만):** 빌더 지문 × 결함 분류(이미 기록 중, `inspection_defects`), 앱 종류, 사용 언어, 원래 의도, 빌더팩으로 실제 고쳐졌는지.
- **왜 비영어권:** 빌더 자체 테스트(Lovable·Replit, 2026)와 개발자용 AI 테스트 도구(Momentic·Autonoma·Shiplight 등)는 영어·개발자 전제 [추정: 공개 자료]. 비영어권에만 있는 실패 유형이 있다 — 다른 언어 출력, 현지 시간대(KST↔UTC) 날짜, 한글 파일명·이름 깨짐 [확정: 2026-10 벤치마크·ssf2026 사례].
- **가격:** 무료(오픈 베타)로 규모 우선, BM은 규모 이후(Bae 검토 중). 비용 통제 = 저가 모델 라우팅 + 무료 1회 검사 상한 + 하루 전체 예산 차단(초과 시 기본 검사로 정직하게 대체).
- **보완 원칙:** 유저 제출 데이터는 프롬프트가 제각각이라 빌더 비교가 섞인다 → **같은 프롬프트 × 여러 빌더 통제 벤치마크**를 정기적으로 병행(2026-10 미용실 벤치마크가 1호).
- **전제:** 엔진 정확도(데이터 품질 = 엔진 정확도). 현재 로컬 실측: 반대 판정 0 · 앱 일치 5/6 · 원인 정확 3/6 [확정: `docs/pilot-2026-10/bench1-agent-local-results-2026-10-05.md`, 로컬·프로덕션 아님]. 프로덕션 재측정 + 새 주제 벤치마크 #2로 일반화 확인 전에는 "검증된다"고 말하지 않는다.

## 3. 장기: 모델·빌더 선택 + 결과 보증
- **차별점:** 각 모델·빌더의 개발 스타일과 실패 지점을 데이터로 알고, **유저 의도에 맞는 모델·빌더를 골라** 결과물을 낸다. 결과는 Simsa 엔진이 "확인한 조건대로 작동함"으로 증명하고, 실패하면 고칠 때까지 돌린다.
- **생성 경로:** 문 (a) 자체 빌드(모델 API 직접 조합) 우선. 외부 빌더(Lovable·Bolt·v0 등)는 공개 API가 확인된 곳만 직접 호출, 나머지는 추천·제휴 연결 [미검증: 빌더별 생성 API 공개 여부].
- **참고 모델 — Genspark:** 70+ 모델·80+ 도구를 조합해 완성품을 파는 구독형. ARR 약 $250M(출시 ~12개월), 기업가치 $2.6B(2026-06) [추정: 보도]. 플랜 Plus 약 $24.99/월(크레딧 1만), Pro 약 $249.99/월 [추정]. **구조 = 유저에게 구독·크레딧을 받고, 모델 회사(OpenAI·Anthropic·Google 등)에 API 토큰 사용량만큼 지불.** 빌더 서비스 구독을 되파는 구조가 아니다. Simsa에 없는 것은 그들의 자금 규모, Simsa에 있는 것은 "작동 증명".
- **하지 않을 것:** 빌더 구독을 묶어 되팔기(원가 그대로·약관 위험·접근 차단 위험).

## 4. 단계
| 단계 | 내용 | 수익 | 여는 조건 |
|---|---|---|---|
| 1 | 무료 측정·검수 + 데이터 수집 | 없음 | 엔진 프로덕션 실측 통과 + 최소 동의·보관 정책 |
| 2 | 빌더·모델 추천("이런 앱은 X가 덜 실패해요") | 제휴 수수료 [미검증] | 빌더 × 앱 종류별 데이터 충분 |
| 3 | 대신 만들기(자체 빌드 + API 열린 빌더) → 검사 → 수정 루프 | 크레딧·사용량 | 문 (a) 실증, 빌더 API 확인 |
| 4 | 결과 보증 구독 | 구독 | 엔진 정확도·수리 성공률 공개 수치 |

## 5. 원가 (검사 1회)
- 정밀 검사(agent 엔진) 로컬 실측: 앱당 약 $0.64(고급 모델 위주) [확정: 로컬 4차 $3.85/6]. 저가 모델 라우팅 후 목표 약 $0.10~0.20 [추정 — 프로덕션 측정 전].
- 무료 100명 × 하루 3회 = 300회/일 × $0.15 ≈ $45/일 ≈ $1,350/월 [추정]. 하루 전체 예산 차단으로 상한을 고정한다.
- 초기 무료 원가는 모델 회사 스타트업 크레딧 프로그램으로 충당 가능성 [미검증 — 신청 필요].

## 6. 수익 구조 — 검수 무료 · 고치기 유료 (Bae 2026-10-05)
원칙: **무엇이 문제인지 찾는 검수 = 무료, 고치는 작업 = 유료(재검사 통과 시에만 청구).** 09-27 BM 문서의 S2(수리 $29, 재검수 통과 시만)와 같은 골격이다. **바뀐 것은 원가**: 정밀 검사(agent 엔진)는 LLM을 쓰므로 무료 검사 1회가 $0.004 → $0.15~0.64로 오른다. 그래서 무료 검사는 이제 "공짜에 가까운 입구"가 아니라 **유료 고치기가 메워야 하는 보조금**이다.

**핵심 등식(활성 유저 1명·월):** 무료 검사 원가 = 4회 × $0.15 = $0.60 [추정]. 고치기 기여 = 결함 발견율 70% × 구매율 × 성공률 × ($29 − 원가 $1.95). **구매율 × 성공률 ≥ 약 3%** 여야 무료 검사 원가를 메운다(예: 구매 5% × 성공 60%).

|---|---|---|---|---|

**규모가 생긴 뒤(정상상태, 활성 1명·월)** — 고치기 + 결과 보증 구독($29/월, 활성의 2%/5%) + 빌더 제휴(약 $0.5, 09-27 근거):
- D2: 매출 약 $1.45 − 원가 약 $0.80 = **기여 약 $0.65** → OpEx $4.4K(창업자 인건비 포함) 손익분기 **활성 약 6,800명** [추정].
- D1: 매출 약 $3.09 − 원가 약 $1.11 = 기여 약 $1.98 → 손익분기 활성 약 2,250명 [추정, Planning 금지].

**민감도:** ①고치기 구매율 −50% → D2 기여 $0.65 → 약 $0.47(손익분기 약 9,400명) ②**정밀 검사 원가 $0.15 → $0.30 → D2 기여 약 $0.05, 사실상 손익분기 없음** — 가장 위험한 변수 ③유입 −50% → 매출 −50%(선형, BM 밖 변수).

**운영 원칙:** 무료 정밀 검사에 월 상한 + 하루 전체 예산 차단(초과 시 기본 검사로 정직하게 대체). 첫 지표는 매출이 아니라 **①정밀 검사 실원가 ②고치기 구매율 ③고치기 성공률** 세 개의 [확정]화.

## 7. 젠스파크형 이코노미 (2026-10-05 계산, 요약)
구독 + 크레딧, 원가 = 모델 API 토큰. D2(전환 3%, 실사용 60%, 원가 비율 80%)에서 활성 1명당 기여 약 $0.22 → 손익분기 약 20,000명 [추정]. 가장 민감한 변수 = 무료→유료 전환율(3%→1.5%면 적자). 앱 작업은 문서·슬라이드보다 토큰 원가가 무거워 마진이 얇다 → 결론: 검수 무료 + 고치기·만들기 크레딧 + **재검사 실패 시 크레딧 환불(결과 보증)**, 마진은 작업별 모델 배정으로.

## 8. 차별점과 사업성 재검토 (2026-10-07, Bae 요청)
**차별점 X-1~X-5**(원래 의도 기준 판정 · 비개발자·비영어권 · 고침 · 작동할 때까지 도는 고리 · 빌더 밖 독립 심사관+빌더별 실패 지도)는 위치 설정에는 충분하나 해자로는 부족 — X-1~X-4는 빌더가 기능 하나로 따라올 수 있다(Lovable 브라우저 테스트·Replit 자가 테스트·수정 [확정: 공개 자료]). **남는 해자 = 독립성(X-5)과 검증된 데이터.** 둘 다 "독립 검수가 필요한 사람"이 있어야 값이 생긴다.
- 추가 차별점(방향, [미검증]): **X-6 증거 기반 검수 영수증**(기준별 통과/실패 + 증거물 + 시각 + 버전, 제출 가능한 문서) · **X-7 기획서·요구사항 대비 납품 검수**(외주·에이전시 결과물을 *받는 사람* — 발주자·소상공인·기관; 만든 쪽 자체 채점은 이해충돌) · **X-8 정확도 공개**(사전 등록 벤치마크 결과를 계속 공개 — "AI 채점을 어떻게 믿나"의 답).
- 유저 두 층(방향): 무료 = 바이브 코더(데이터·유입 입구) · 유료 핵심 후보 = 결과물을 받는 사람(외주 발주자·에이전시 고객·소상공인). 첫 검증 = 엔진 G1 통과 후 외주 경험 있는 소상공인·스타트업 인터뷰.

## 9. 무료 데이터 수집 + 투자로 버티기 — 조건과 순서 (2026-10-07)
- **데이터가 해자가 되는 이유:** "여러 빌더 × 원래 의도 × 증거로 검증된 결함 × 수정 성공 여부"를 함께 가진 곳이 없다(비영어권은 더 비어 있음). 빌더의 물량(하루 수만~10만 프로젝트 [추정])과는 양이 아니라 **독립 검증 라벨의 질**로 경쟁한다.
- **전제 3개(모두 미증명):** ① 라벨 신뢰도(엔진이 틀리면 데이터 가치 0) ② 유입 채널(자연 유입만으로 연 가입 ~100명 [추정, 09-27]) ③ 데이터 구매자(AI 연구소·빌더 [추정]). 동의율 27~40%면 판매 가능 기록은 수집량의 약 1/3.
- **12개월 1만 건 목표 원가:** 검사 약 2.9만 회 × $3 ≈ $86K + 고치기·재검사 ≈ $30K + 인프라 ≈ $10K → AI·인프라 약 $125K [추정]. 인건비 포함 시드 $1~2M로 18개월 [추정].
- **유저 없이 데이터를 만드는 길(우선):** 같은 프롬프트 × 여러 빌더 **통제 벤치마크를 직접 생산**(예: 프롬프트 50 × 빌더 6 = 300셀, 약 $3~5K [추정]). 유입·동의 문제 없음, 빌더 비교가 깨끗함(장기 "의도에 맞는 빌더 고르기"의 근거), 공개 벤치마크로 신뢰·홍보(X-8).
- **돌아오는 경로:** 데이터 판매(연구소·빌더) · "Simsa 검증" 검수 API · 외주 납품 검수(B2B) · 인수 · 장기 멀티 모델 구독.
- **투자자가 반드시 물을 것:** "라벨이 맞다는 증거는?" · "데이터를 사겠다는 곳이 있나?" → 아래 로드맵 ②·②.5·③으로 답한다.

## 10. 로드맵 (2026-10-07 갱신, Bae 승인)
① **검사 엔진 완성**(v2 증거 고리 — `docs/simsa-inspector-v2-design-2026-10-07.md`, 설계 잠금 V-1~V-8) → ② **채점을 더 잘한다는 증명**(관문 G1 13앱 로컬 · G2 프로덕션 3회 · G3 새 주제 · G4 고리) → **②.5 통제 벤치마크 자체 생산 + 공개**(프롬프트 × 빌더, 유저 없이 데이터) → ③ **데이터 구매 의향 확인**(연구소·빌더 1~2곳 관심·LOI) + 유료 대상(받는 사람) 인터뷰 → ④ **투자 유치** → ⑤ **무료 공개로 규모** → ⑥ **멀티 모델 구독 플랫폼**(Conclave형 다중 에이전트 빌드 + 화이트박스 측정 + 결과 보증 크레딧; 07-08 Conclave EOL 결정의 번복은 그때 명시).
실측 근거(2026-10-07): 같은 v1 엔진을 강한 모델로만 돌리면 원가 2~3배($0.61~1.29/런)에 정확도 동일(Bolt 의도 불일치 여전히 놓침) → 정확도는 모델이 아니라 설계 문제 → v2.
